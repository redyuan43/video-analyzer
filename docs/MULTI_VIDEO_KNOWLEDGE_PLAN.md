# 视频知识工作流分档方案

## 第一档：单视频文档闭环

目标是让一条视频在资源受限的 NX2 上稳定产出可追溯的 Markdown 文档，而不是把整段视频、全部帧和全部原始文本一次塞进文本模型。

流程：

1. 核心分析完成 ASR、OCR、VL 和操作手册。
2. 学习账本按章节整理可用证据。
3. 多文档阶段按章节构造有限证据包，优先保留 OCR、VL、字幕/ASR、操作手册和页面上下文。
4. 本地 Qwythos 对每章生成结构化结果，并在 `docs_analysis/orin/chapters/` 写入检查点。
5. 单次跨章节总览汇总章节结果，再程序化写出：
   - `docs_analysis/knowledge_notes.md`
   - `docs_analysis/deep_report.md`
   - `docs_analysis/operation_manual_review.md`
   - `docs_analysis_chapters/knowledge_notes_v2.md`
   - `docs_analysis_chapters/deep_report_v2.md`
6. 证据复核、联网补证据、问答索引和最终发布从同一运行目录继续执行。

约束：

- Qwythos、ASR、OCR 和 VL 必须通过本地模型锁互斥运行。
- 章节输出预算是随证据量变化的软上限，不采用固定的短输出截断。
- 章节检查点使中断恢复只重跑未完成章节。
- 当前最终交付只保留 Markdown，不生成 PDF 或 Word。

## 第二档：多视频知识库

当多个单视频运行目录已经稳定产出后，再建立跨视频关联层。第一档的 Markdown、章节 JSON、证据索引和问答索引是第二档的输入，不重跑 ASR/OCR/VL。

建议的离线构建步骤：

1. 为每个视频写入不可变的 `video_id`、来源、标题、发布时间、主题、章节和证据定位。
2. 按章节和证据片段切块，保留 `video_id`、章节时间范围、帧时间戳、证据类型和原始文件路径。
3. 为切块建立混合检索：
   - 关键词/BM25 负责专有名词、型号和精确术语；
   - 中文文本 embedding 负责语义召回；
   - 结果合并后再做 rerank。
4. 回答跨视频问题时先检索，再用少量高分证据生成答案；答案必须返回视频、章节和时间定位。
5. 对相互冲突的事实保留多源证据，不在索引阶段强行合并成单一结论。

推荐的后续选型原则：

- Embedding 优先选择中文检索表现成熟、可离线批处理的模型。
- Reranker 只处理初召回的少量候选，避免成为 NX2 的持续 GPU 负担。
- 向量索引和 BM25 索引放在更适合常驻服务的主机；NX2 只负责单视频的本地推理闭环。

本阶段暂不实现。开始条件是至少两个单视频样本完成端到端验收，并确认单视频输出结构无需再改。
